## 3. 아키텍처 원칙 (Architecture Principles)
- 이 프로젝트는 다음 원칙을 따른다:
  1. 판단 로직과 실행 로직을 분리한다 (classify → decide → act 파이프라인)
  2. 모든 판단에는 근거(evidence/citation)를 남긴다 — 근거 없는 답변 금지
  3. 실패 시 안전한 기본값(escalate to human 등)으로 fallback 한다
  4. 프롬프트 인젝션/탈옥 시도로 의심되는 입력은 별도 플래그 처리 후 사람에게 넘긴다
  5. 단일 LLM 호출이 곧 아키텍처가 되지 않도록 한다 — 입력 로드/정규화, 컨텍스트 구성, 모델 호출, 응답 파싱, 스키마 검증, 라벨 강제, 재시도, 로깅, flag 여부 결정을 각각 별도 책임으로 분리

## 3-1. 출력 계약 (Output Contract) — 코드 쓰기 전에 채운다
> 9월 Orchestrate 피드백: 계약을 assert로 나중에 붙이지 말고 처음부터 적을 것.
- 출력 컬럼/타입: [컬럼별 허용값·형식]
- 필드 간 규칙 (예: status가 X면 Y 필드는 비어야 함 / 금액은 A 이하): [...]
- **단일 진실원천**: 핵심 예측/시뮬레이션은 한 곳에서 한 번만 계산하고, 모든 출력 필드는 선택된 결정 하나에서 함께 도출한다. 필드마다 따로 계산하는 휴리스틱 금지.
- 출력 직전 `validate_row()`로 위 규칙을 전부 검사한다. 통과 못 하면 그 행은 안전한 기본값으로 대체하고 로그에 남긴다.

## 3-2. 근거 부족·모순 정책과 모델 실패 폴백
- 근거가 모호하거나 서로 모순될 때의 우선순위와 보수적 기본값: [예: 명시적 정정 > 최신 동일 출처 > 확정 기록 > 추정, 그래도 모호하면 보수적 쪽]
- 입력 검증 규칙(데이터셋 필드별 허용 범위·누락 처리): [...]
- 모델 호출이 실패(쿼터·타임아웃·깨진 JSON)하면: 재시도 후 해당 사실을 "근거 부족"으로 처리하고 보수적 기본값으로 계속 진행한다. 한 행의 실패가 전체 실행을 멈추면 안 된다.
- 충돌하는 입력을 다루는 few-shot 예시 2~3개를 프롬프트에 넣는다 (추출 방법뿐 아니라 충돌 해소 방법 포함).
- 고정 파이프라인이라면, 모델이 제한된 도구/단계 중 고르고 이유를 남기는 작은 router가 필요한지 결정하고 그 이유를 Decision Log에 적는다.
- 디버깅 요청에는 요약 대신 원본 에러/스택트레이스를 그대로 붙인다.

## 3-3. AEL 사용 규칙
- 원장 파일: `data/ael.db` (append-only, 재실행해도 삭제·재빌드 금지). 프로젝트 시작 시 첫 에이전트 함수를 쓰기 전에 `ael-ledger-setup` 스킬로 구축한다.
- 1 사이클 = 요청/행 1건. Verification 단계에서 `validate_row()`를 실행한다.
- 특정 행이나 낮은 confidence 패턴을 디버깅할 때는 코드를 읽기 전에 `ael-ssot-debug` 스킬을 먼저 쓴다.
- 인터뷰 준비: "이 판단을 어떻게 검증했나"의 근거는 원장이다.

## 4. 입력 하나 끝까지 따라가기 체크리스트 (Trace-One-Input Self-Check)
> 시스템을 설명하기 전에, 입력 하나를 골라서 아래 질문에 답할 수 있는지 확인한다.
- [ ] 어디서 읽히는가?
- [ ] 어떻게 정제(clean)되는가?
- [ ] 어떤 컨텍스트가 추가되는가?
- [ ] 모델은 어디서 호출되는가?
- [ ] 어떤 스키마로 응답을 받는가?
- [ ] 응답 이후 코드는 무엇을 검증하는가?
- [ ] 무엇이 로깅되는가?
- [ ] 언제 재시도/보류(abstain)/리뷰 요청으로 넘어가는가?
- [ ] 최종 출력은 어디에 쓰이는가?

## 5. 폴더 구조 (Repo Layout)
```
code/           # 실제 에이전트 코드
data/           # 입력 데이터 (제출 시 제외 대상일 수 있음, 규칙 확인)
eval/           # 평가 하네스 및 테스트 케이스
output/         # 최종 예측 결과물 (output.csv 등)
transcripts/    # AI 채팅 로그 (log.txt)
```
- 파일명에 `helper`, `final`, `utils`, `test2` 같은 이름 쓰지 않기 — 역할이 드러나는 이름 사용
